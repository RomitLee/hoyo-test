# 主从机独立发版

主机 V2.1.0、从机 V2.0.0、通信协议 1。产品版本可不同，协议相同即兼容。V1.x 和 V2.0.0 旧从机没有协议字段，按已知发布版本映射为协议 1；未知版本显示兼容性待确认，明确不支持的协议显示协议不兼容。

## 更新与打包

新客户端读取 `/api/v1/updates/latest/master` 或 `/api/v1/updates/latest/slave`。每个角色各有签名清单，schema3 将程序类型纳入签名，避免交叉使用清单。版本、下载路径、大小、散列、目录和启动程序均受签名保护。schema2 校验仍保留。

仅构建主机：`./scripts/build_windows.ps1 -SkipInstall -Role master -ReuseDirectory dist-v200 -OutputDirectory dist-v210-independent`。从机同理使用 `-Role slave`。未改动的一端从既有发布目录的签名压缩包恢复并验证版本、散列和大小，最终 ZIP 原样复制，避免重新打包。复用目录必须保留两端安装包、清单和 legacy 目录。默认 both 同时构建两端。

本次 V2.0.0 从机 ZIP 与正式发布字节一致。主机设置的遮挡日志规则由服务端执行，无需改从机。尚未发布的新版从机源码已经准备独立版本和协议字段；以后发布新版从机前应先部署支持这些字段及角色清单的新服务端。

## 一次过渡

旧客户端更新请求没有程序类型，主机和从机地址及 User-Agent 相同，因此无法只给旧主机自动推送 V2.1.0，同时保持旧从机完全不更新。保留旧签名 schema2 清单 V2.0.0 作为 `/updates/latest` 返回值，防止旧从机被误更新。旧主机需要手动安装一次 V2.1.0，之后使用角色入口自动更新。无需升级或重启现有 V2.0.0 从机。

部署时上传 `release-manifest-master.json`、`release-manifest-slave.json`、`legacy-release-manifest.json`、两端 ZIP 和 legacy 子目录。legacy 保留旧包原始字节，避免相同文件名指向新版主机。先上传包和后端，最后原子切换清单；角色清单不得替换为另一角色的清单。`release-manifest.json` 是本地工具使用的主机清单副本，旧客户端接口优先返回 legacy 清单。

## 2026年10月23日后续过渡

对象识别功能上线后，主机V2.2.0、从机V2.1.0、服务端2.8.0。当前旧更新入口提供合法签名 schema2 V2.1.0：从机包是新版V2.1.0，主机包是既有V2.1.0原始包，两端实际版本均与该清单一致。因此现有从机V2.0.0可自动升级，旧主机V2.0.0也可自动先升级到V2.1.0，再进入主机独立通道升级至V2.2.0，不再必须手动过渡。新客户端以后分别使用自己的独立更新入口。历史下载保留在 history/角色/版本 目录；新包使用带版本号的文件名，发布时不覆盖旧包字节。
