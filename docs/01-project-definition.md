# 01. 项目定义与识别目标

## 1. 输入与输出

### 输入

分析电脑接收来自视频采集卡的实时视频流，或者接收已录制的视频文件。输入可能包含：

- 1920×1080 或 2560×1440 游戏画面。
- 30/60 FPS 视频流。
- 游戏画面、桌面、登录页、弹窗和黑屏。
- 视频采集延迟、丢帧、压缩噪声和缩放比例变化。

### 输出

输出是带时间戳的事件记录，而不是“每一帧一条文字”：

```json
{
  "event_id": "evt_000001",
  "timestamp_ms": 192000,
  "timestamp": "00:03:12.000",
  "type": "map_entered",
  "confidence": 0.96,
  "payload": {"map_name": "北俱芦洲"},
  "evidence": {
    "frame_index": 5760,
    "source": "ocr+scene_rule"
  }
}
```

## 2. 事件分层

不要把“看到一个文字”直接等同于“完成一个事件”。建议分为三层：

### 观察 Observation

模型或图像算法直接观察到的事实：

- `inventory_panel_visible = true`
- OCR 读到文字 `北俱芦洲`
- 检测到战斗界面标志
- 检测到技能图标
- 读到数字 `12445`

### 状态 State

经过连续帧确认后的当前状态：

- `scene = world_map`
- `map_name = 北俱芦洲`
- `panel = inventory`
- `battle = active`

### 事件 Event

状态发生变化时生成一次事件：

- `map_entered`
- `inventory_opened`
- `battle_started`
- `skill_used`
- `damage_dealt`

这三层分开后，偶尔 OCR 错一个字不会立刻制造一条错误的业务事件。

## 3. 识别目标拆解

| 用户希望记录的内容 | 推荐识别方式 | 备注 |
|---|---|---|
| 打开游戏 | 场景分类/固定区域模板 | 只需确认主界面出现 |
| 进入地图 | 地图名 ROI + OCR + 状态变化 | 地图名通常比整屏 OCR 容易 |
| 打开背包 | 背包面板检测或模板匹配 | 固定 UI 优先不用大模型 |
| 背包物品 | 物品格检测 + OCR/图标分类 | 文字和图标可以分两路 |
| 切入战斗 | 战斗 UI 检测 + 多帧确认 | 不能只看单帧闪烁 |
| 使用技能 | 技能区域变化 + 技能名 OCR/图标分类 | 需定义“使用”的证据 |
| 伤害数字 | 伤害数字 ROI + OCR | 需要去重和时间关联 |

## 4. “发生了什么”的判定原则

每个事件需要记录：

- 事件类型。
- 发生时间：优先使用视频时间戳或采集时钟。
- 证据帧编号。
- 识别来源：检测、OCR、模板、规则或人工校验。
- 置信度。
- 原始文本和归一化文本。
- 关联的场景、战斗或回合 ID。

不要只输出一句自然语言。自然语言报告应该由结构化事件二次生成。
