# 游戏面板识别与操作日志

## 支持的识别码

| 识别码 | 界面 | 打开时的日志 |
| --- | --- | --- |
| `inventory` | 背包 / 道具行囊 | 打开背包 |
| `give` | 给予面板 | 打开给予面板 |
| `trade` | 交易面板 | 打开交易面板 |
| `attributes` | 人物属性及其师门、辅助、修炼页 | 打开属性面板 |
| `stall` | 摊位面板 | 打开摊位面板 |
| `stall_records` | 摊位记录面板 | 打开摊位记录面板 |
| `default` | 默认游戏界面，没有检测到上述面板 | 关闭面板，返回默认游戏界面 |
| `unknown` | 黑屏、缺少游戏界面标志或无法确认 | 不生成面板切换日志 |

## 识别方法

使用本地图像模板定位面板标题，并检查颜色，避免将红色“摊位记录”按钮当成蓝色记录窗口标题。
属性面板的四种子页使用不同模板但归为同一识别码，切换属性页签不重复记录打开。
模板仅包含通用标题和聊天栏“当前”标志，没有保存角色名称、账号和完整游戏截图。
原始截图保持在用户指定文件夹，不修改或上传。

640×480 和 800×600 下，游戏面板可能保持相同像素大小；不能根据整个游戏窗口的分辨率
推断背包等比例缩小。背包容量定位增加固定 0.8 模板比例，保留原有多尺度定位方式。
其他面板的物品网格不参与背包容量判断。

## 日志规则

- 连续 3 个分析帧确认新面板后，只记录一次打开；保持打开不会每帧重复记录。
- 连续看到默认游戏界面至少 1 秒后记录返回默认界面；无法确认的画面不会直接判定关闭。
- 日志时间使用实际确认时的北京时间，格式为 `2026年10月20日10:31:20打开背包`。
- 日志附带窗口、区服、角色、识别码和置信度，便于区分多窗口操作。
- 切换面板只记录新观察到的打开，不推断旧面板已经关闭，因为它可能被覆盖。
- 手动暂停、最小化或采集长时间断帧会清空未完成的连续确认，避免跨暂停拼接证据。
- 使用现有离线上报队列，联网后补传原始发生时间，服务端按事件 ID 去重。
- Windows 主机和手机 H5 的“监控日志”展示相同记录，不触发背包告警、铃声或 Bark。

本地可读文本：`runtime/events/panel_events.log`。
结构化事件：默认与原背包事件一同保存到 `runtime/events/inventory_events.jsonl`。
这两个路径相对于程序目录；如修改事件日志路径，面板文本保存在同目录。

## 样本验证

用户提供 80 张 640×480 截图：背包 13、给予 15、交易 4、属性 14、摊位 13、摊位记录 6、默认界面 15。
模板来自其中 10 张截图的通用界面区域。对全部样本回放，80/80 分类正确。
将原图以原生 UI 大小放到 800×600 画布、整体平移后追加验证，80/80 分类正确。
这是提供样本及合成画布的回放结果，不代表已经覆盖全部真实 800×600 界面、遮挡和缩放情况。
背包 13 张样本均定位成功，结果覆盖未满、接近满和已满。

复现：

```powershell
.venv/Scripts/python.exe scripts/evaluate_panels.py --samples 'C:/Projects/10月训练用' --check-800
```

详细结果：`runtime/panel-evaluation/report.json`。实际部署还需同时更新从机、主机与服务端；
已于 2026-10-20 随主机/从机 V1.5.0、服务端 2.3.0 和新版 H5 同步上线。
V1.4.0 客户端可沿用原签名密钥自动升级。
