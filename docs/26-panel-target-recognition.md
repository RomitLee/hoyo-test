# 给予、交易对象识别（主机V2.2.0、从机V2.1.0，已上线）

## 用户可见行为

从机识别到给予或交易面板后，只读取该面板对象昵称和等级的两个小区域。打开面板的日志会附带已确认对象；初期未确认时显示对象未识别，之后确认成功会补一条对象识别日志。同一面板内对象昵称或等级变化，三次连续观测稳定后新增对象日志。主机和 H5 都显示昵称和等级；给予、交易类型筛选包含对象变更记录。

例：2026年10月23日18:00:00 打开给予面板，对象：剑侠旧梦，109级。

只记录看到了谁，不推断给予成功、交易完成或资金到账。

## 方案与边界

面板位置继续使用原模板定位；通过标题锚点计算对象区域，支持原生640×480以及800×600内的原生尺寸界面和窗口移动。文字识别使用 ONNX Runtime CPU 和 PP-OCRv4 移动端识别模型，不使用 YOLO 或云端文字识别。字符字典来自模型，代码没有硬编码这四位玩家的昵称，也没有简繁转换。

针对黄色小字号文字生成四种留白版本，至少两种一致且通过字符置信度门槛才使用。昵称和等级作为一对连续三帧确认，等级限制1～175。遇到鼠标彩色遮挡、边缘截断、字段缺失、两种候选冲突、无模型时标记未识别；识别异常不会终止现有背包、现金或窗口监控。看不清时立即清空当前识别结果中的对象信息，连续失败三帧后记录一次对象未识别。短暂失败恢复到同一对象不刷重复日志；持续失败后恢复会重新记录。离开面板、未知画面、暂停、最小化或采样断层均重置对象确认状态。

截图样本验证不等于覆盖所有昵称、特殊符号、皮肤及缩放。任意字体或罕见字仍可能无法识别，程序保守记录未识别，不使用上一位玩家作为兜底。

所有游戏截图和区域识别都在从机本地完成，只上报昵称、等级、置信度和识别状态。每个进程共享一个 CPU 推理会话，限制推理线程数为1，字段图像相同则复用缓存；不会每帧重复加载模型或运行推理。模型随从机包提供，首次运行不联网下载。

## 数据与兼容

新增事件类型 panel_target_changed，仍在监控日志内。新增可空字段 target_name、target_level、target_confidence、target_status。SQLite 仅增加可空列；旧客户端不传这些字段继续工作。新服务端拒绝部分昵称等级、越界等级、无状态或将旧对象附到未识别状态的请求。账户隔离和 event_id 幂等规则不变。

主机优先按结构化对象字段显示，避免未识别状态却显示旧 message 的对象。H5 使用 textContent 显示昵称。现有监控日志类型筛选按 panel_type 工作，无需新增筛选入口。

发布时应先升级服务端（含 H5），再发布支持对象事件的主机和含模型的从机；旧版服务器拒绝陌生字段，不能先升级从机。本功能已于2026年10月23日发布：主机 V2.2.0、从机 V2.1.0、服务端2.8.0。两端均有实际改动，分别递增版本。旧从机V2.0.0可自动更新至V2.1.0，旧主机V2.0.0可先自动更新至V2.1.0，再通过独立通道更新至V2.2.0。本次未提交或推送 GitHub。详见27号上线记录。

## 本地验证

四张用户原图在源码及按正式从机 spec 构建的独立测试程序中均识别正确：

|对象昵称|等级|
|---|---|
|剑侠旧梦|109|
|图图防御符4|144|
|昌少带你飞|109|
|惜别离|175|

第二张图昵称末尾数字4按原图保留。回归样本只保存两个文字字段（tests/fixtures/panel_target_fields.npz），没有保存完整游戏截图或账号ID。

客户端相关测试92项（识别、面板事件、上报、主机、更新、金额及从机界面）、服务端41项均通过；代码检查和 H5 JavaScript 语法检查通过。冻结程序依赖自检和四张原始截图诊断通过。冻结程序验证报告位于 runtime/panel-target-frozen-verification.json。build/target-ocr-verification 是打包验证产物，不是正式版本包，不可当作 V2.0.0 新版本分发。其版本常量沿用未发版源码，正式线上安装包没有修改。

诊断入口：从机程序 --diagnose-target 图片路径。结果写入该程序 runtime/panel-target-diagnostic.json，包含面板类型、昵称、等级、失败原因和生成的对象日志；不启动桌面监控或连接服务端。

新增离线模型来源、SHA-256 与许可说明见 assets/ocr/README.md，运行依赖只有 onnxruntime，开发阶段用于比较模型的 rapidocr Python 包不是项目运行依赖。主机打包不携带识别模型。
